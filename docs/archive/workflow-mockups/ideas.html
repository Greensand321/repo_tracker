Eight ways to organize the same branches

Same deterministic engine, same branch data — eight different organ­izing metaphors. Each is a static visual (no data wiring), so you can judge the shape of the workflow before we commit. The advisor rail can attach to any of them; it is omitted here to keep each idea pure.

01 · Kanban with WIP limits

Columns are states you act on. Swimlane color = repo. The point is the WIP limit: too many branches in flight is the actual disease, so the board makes over-commitment visible and forces closure.

StrongAnswers “what’s next?” instantly; WIP limits directly shrink branch count.
WatchA branch can be both “in review” and “stale” — columns must be single-valued.

02 · Triage inbox (process to zero)

Every branch is a conversation you haven’t finished. You drain the queue to zero. The advisor drafts the action for the selected item; you approve or edit. Best when the pain is backlog dread rather than “where was I?”.

StrongMakes “dozens of branches” feel finite and closable; great for stale cleanup.
WatchCan feel like admin work; needs a clear “skip/archive” affordance.

StrongPerfect for re-entry after absence; exposes abandoned threads.
WatchHistorical, not actionable — pair with a board or table.

StrongInstant “is anything on fire?” with zero reading.
WatchImprecise — you can’t select or act easily; can be gimmicky.

07 · Runbook / conductor

StrongBest match for “a workflow I want to adopt”; hard to skip steps.
WatchLess flexible for ad-hoc questions; routine design is the work.

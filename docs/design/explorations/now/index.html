Happening now five ways to say the same thing
The band as it ships prints five labelled rows — for, last, done, open, now — and on a branch that finished cleanly, four of them say the same sentence four times. That is not a styling problem. Four background stations each write a full sentence about one branch, and the page prints all four whether or not they differ. The band should answer one question first — is there anything here for me? — and only then, if asked, what happened.
  • It repeats. For, last, done and now are one fact in four dresses. Nothing should be printed twice, however neatly it is labelled.
  • Labels are filing, not reading. Five keys mean the reader assembles the sentence. That assembly is the mental load the tool exists to remove.
  • Nothing is ranked. "Nothing looks unfinished." — a non-event — gets the weight of a finding, and the verdict that actually decides what you do sits last.
  • Identifiers leaked into the prose. "Pull request #630 merged…" — D90 already ruled that names are identifiers, not words. A number you never act on belongs in a chip, not a sentence.

The change underneath all five

Every design above gets shorter the moment the summary station stops writing four sentences for a page that wants one. The contract changes from last / done / open to state (one word), gist (one clause, no identifiers in it) and next (the one thing left, or null) — and PROMPT_VERSION goes to v3 so nothing written on the old shape survives. The four-sentence recap stays in the data for the fold in N2 and for search; it stops being the thing the band prints.

last + done + now on a finished branch → one clause
open == "Nothing looks unfinished." → null, and nothing is drawn
"Pull request #630 merged" → state: done, and a chip that reads merged

Rule 4 holds either way: the fact goes in the structure, and each design above is only a different rendering of it.

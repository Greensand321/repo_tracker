Partly superseded, 17 Sep (evening). The four background calls are no longer run by three separate loops: they are derived onto one board and run by one dispatcher that checks each job against the snapshot before counting it done (D68, D69). What each call sees, decides and may never do — the whole point of this page — is unchanged, and so is the cost model. What changed is who runs them, in what order, and what happens when one fails: it parks, visibly, instead of repeating. See plans/workroom.md.

The short answer

The assistant is six separate prompts, fired at different moments. Four run on their own in the background; two run because you pressed something. Four of the six may look things up before they answer (steps 3–6 of the workroom), one of those — the advisor, ⑤ — may put work on the board, and none of them may write a goal or a vision as your own. Everything any of them writes goes to Plane B — never to a repo.

Every path, from the moment it wakes

Dashed lines are the paths where nothing is spent. On a fleet that has not moved, every dashed line is taken and the whole pass costs zero.

The six calls, in detail

Each one is a fresh request with no memory of any other. Nothing is carried between them except what got written to disk.

①

Summarise a branch

background · once per branch per head
Sees
One branch: repo, name, ahead/behind, diffstat, CI, PR, and up to 25 commit messages with bodies. Nothing about any other branch.
Decides
A title, a 1–3 sentence summary, a progress verdict, and which SHAs it rested on.
May not
Cite a SHA the branch does not contain — invented ones are dropped before you see them.
Cached on
head SHA + prompt version + model
Writes
A recap — last, done, open — plus the title, the progress and the evidence (D89). A merged branch is read from its pull request's commits.
Prompt
server/advise/prompt.ts → SYSTEM_PROMPT (v2)
②

Draft what a branch is for

background · once, if there is no vision
Sees
One branch, same as ① but without the diffstat.
Decides
A falsifiable sentence, or declines. Declining is a success: a purpose nothing could contradict is worthless as a yardstick.
May not
Mark its own draft as confirmed. It is stored as proposed and shown as a guess until you say otherwise.
Cached on
nothing — it runs once, then the vision exists
Prompt
server/advise/vision.ts → DRAFT_SYSTEM
③

Compare the vision to what happened

background · per branch, per head, per vision
Sees
The vision text, then the same branch detail as ②.
Decides
on-track, drifted (and must name what it is doing instead), done, or unclear.
May not
Return overtaken. A branch judged alone cannot know another branch beat it to the punch, so that verdict is downgraded to unclear if it tries.
Cached on
head SHA + the vision text + prompt version + model
Prompt
server/advise/vision.ts → ASSESS_SYSTEM
④

The brief

background · once per change to anything
Sees
Every branch at once (capped by askBranchCap, default 60): its vision, its summary, its verdict, its CI and PR. Plus every goal, its note and its members.
Decides
The brief itself; a state per goal with its reasoning; and which branches have been overtaken by which — the one finding that needs the whole fleet.
May not
Judge a goal that does not exist, cite a branch not under that goal, or say a branch overtook itself. All three are dropped.
Cached on
a hash of every head SHA, vision, verdict and goal
Prompt
server/advise/brief.ts → SYSTEM
⑤

Ask the advisor — the desk

you pressed Ask
Sees
A compact block per branch — what it is FOR, what it DID, how they COMPARE, its goal — plus every goal and its judgement. The same shape as ④, plus the verdicts.
May look up
what_changed (free, the dated history) and dispatch — the one write any tool has: put a job on the board, through the same door the page's buttons use. It queues; it does not do. Off with the other lookups (toolsEnabled), when it is one turn as before.
Decides
Four sentences of plain English. Asked to rank: an ordered list of real branches, one reason each — an answer, nothing written. Asked to regroup: a proposal of goals by title and branches under each, filed only when you press file them like this.
May not
File anything itself, start work the page could not ask for, or describe the result of work it started — it says "started", never "done" (D84).
Cached on
nothing — you asked, so you get a fresh answer
Prompt
server/advise/ask.ts → SYSTEM · the tool in server/tools/desk.ts
⑥

Describe several branches at once

you pressed “describe several”
Sees
Your paragraph, and a one-line list of every branch that exists.
Decides
Which branches you meant, and one vision each. It may also flag one as finished or dead.
May not
Name a branch that does not exist, propose the same branch twice, or write anything before you press Apply.
Cached on
nothing
Prompt
server/advise/vision.ts → DISTRIBUTE_SYSTEM

What it can never do

  • Touch a repo. No prompt has a write tool, and no code path from any of the six reaches git. Plane A is read-only forever.
  • Mark a goal done. It writes a judgement; Goal.done stays your boolean and only an accept click flips it.
  • Confirm its own vision. A draft is proposed until you say otherwise, and a proposed vision is marked everywhere it appears.
  • Decide a drift is your fault or its own. It reports the drift and offers you both answers.
  • Invent evidence. Every SHA, branch name and goal id it returns is checked against the snapshot and dropped if it does not exist.

Tools: none, yet — and that is deliberate

All six calls are single-turn. The assistant cannot fetch anything, cannot follow up, and cannot look at a second branch. Whatever it needs is written into the prompt before it runs.

Why — and a correction, 17 Sep. The caution here was over-calibrated. It came from one real burn (response_format failing whole requests on some Zen models) and was generalised further than that evidence supports: modern models handle a handful of tool calls without difficulty, and the turn counts here are tiny. The floor that matters is not the model's capability but the provider being swappable by design (D32) — so tools ship with native calling where it works and a plain JSON protocol where it does not, same catalogue either way. npm run probe decides which, not whether.

What tools actually wait on is the predicate check, which now exists: tools without a way to tell whether the job worked is just a longer guess. The catalogue and the order are in plans/workroom.md §4 and §8.

Two traps if you edit a prompt by hand. Every one of them ends with an exact JSON shape. Change that shape and the parser returns nothing — silently, because a failed parse is treated as “the model declined”. And nothing regenerates on its own: bump the matching PROMPT_VERSION beside it, or you get a quiet mix of old reasoning and new.

Where to change things — proposed

Editing TypeScript to tune a sentence is the wrong shape, and it collides with rule 7: nothing hardcoded. The proposal, not yet built:

  • A house-style block per call, edited in the app. The guardrails — return this JSON, do not invent SHAs, decline rather than pad — stay in code where they cannot be broken. Your preferences get appended underneath. “Lead the brief with what is blocking me. Never use the word ‘currently’. Two sentences, not five.”
  • The house style becomes part of the cache key, so editing it regenerates everything that used it — automatically, no version to remember.
  • A full-edit escape hatch, clearly marked, with “restore default” next to it and a visible warning on screen the first time a parse fails.

That is stage C of docs/plans/agent-memory-plan.md, arriving from the other direction: there it grows out of feedback on outputs, here out of wanting to set the rules up front. They are the same store.
